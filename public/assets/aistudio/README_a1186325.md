# Public Access to Government News — Version 8 Front-end Prototype

## Files
- `index.html` — website structure, article access tools, administrator login and publisher forms
- `style.css` — responsive design, forms and accessibility styling
- `script.js` — search, filters, article audio, English/Sesotho sample content, demonstration login and browser-local publishing

## Run in Visual Studio Code
1. Extract the ZIP file.
2. Open the `government_news_frontend` folder in VS Code.
3. Open `index.html` in a browser, or install the **Live Server** extension.
4. Right-click `index.html` and select **Open with Live Server**.

## Demonstration administrator login
- Username: `admin`
- Password: `Admin123!`

After signing in, use the Administrator dashboard to create a publisher username and temporary password. Give the credentials directly to the intended publisher. The publisher can then sign in and add sample news articles. A publisher can also enter an optional Sesotho title, summary and article body. The language selector shows those fields when provided; sample articles have demonstration Sesotho text.

## Features
- Search stories, filter by topic and search the archive.
- Read individual articles, share/save stories and listen to article text using browser text-to-speech.
- Switch the interface and available sample article text between English and Sesotho.
- Administrator creates publisher accounts; publisher login gates the demo publishing form.
- Publisher can add English content and optional human-reviewed Sesotho content.
- Audio articles, administrator-managed SMS alert drafts visible to publishers, district selector, topic-based recommendations and high contrast.

## Important security and functionality limitations
**This is only a front-end demonstration, not a secure authentication system.** The admin username/password are embedded in JavaScript; publisher usernames and passwords are stored in browser local storage without secure password hashing; a user with access to the same browser can inspect or change them. These demo accounts do not work across different computers or browsers. Do not use real passwords or confidential information, and do not use this prototype to publish real government announcements.

A production service must move authentication and authorisation to a server, hash passwords securely, use HTTPS, enforce role permissions and session expiry, protect against common web attacks, log account activity, and store articles in a shared database. Admin accounts should be provisioned securely and temporary passwords should be changed on first sign-in.

Other limitations:
- Article entries are stored only in the current browser; they are not shared with other users.
- Text-to-speech depends on browser/device voices. Sesotho speech may not be supported even when Sesotho text is displayed.
- The included Sesotho text is demonstration content and should be reviewed by a fluent Sesotho speaker before use. Custom article translations must be entered by the publisher; there is no automatic translation service.
- The SMS form does not send messages. Real alerts require an SMS provider, backend, consent management and unsubscribe handling.
- The district selector is illustrative rather than a geographically accurate map. Recommendations are topic-based, not AI-powered.
- Sample stories are not official announcements. A live website requires verified official content, approvals and source links.

## Latest changes (Version 5)
- Audio is available from each news card and inside the opened article using the **Listen to article** button; the separate audio chooser panel has been removed.
- Public visitors no longer have an SMS alert sign-up form. SMS alert drafting is available only in the administrator dashboard.
- The administrator can prepare an alert by district, choose a category, write a message up to 320 characters, and save it as a local draft. Drafts are listed in the administrator dashboard.
- The SMS composer is still a front-end demonstration: it does not send SMS messages. Live delivery requires a secure backend, an approved recipient list, consent controls and an SMS provider.
- Browser-local login and drafts are not suitable for a production government service.


## Version 6 update: language switching while reading

Open any news article and use the **Reading language / Switch language** selector inside the article. Switching between English and Sesotho updates the article text where a Sesotho translation is available, and the **Listen to article** button reads the selected-language version. The site-wide language selector and article selector stay synchronised. Sesotho text-to-speech depends on whether the user's browser/device has a suitable Sesotho voice installed; if it does not, audio may sound incorrect or may not play. This prototype uses sample translations and does not automatically translate articles.


### Version 7 changes
- Removed the Lesotho Sign Language feature for now.
- Moved SMS alerts out of the public access area and into the administrator dashboard.
- Publishers can view administrator-prepared SMS alert drafts in their dashboard; only the administrator can prepare drafts.
- SMS drafts are saved in this browser only; this prototype does not send real SMS messages.


## Version 8: publisher dashboard and review workflow
- Publisher dashboard shows totals for articles, drafts, pending review and published stories.
- Publishers can save unfinished articles as drafts, edit their own drafts or returned articles, delete drafts, and submit completed articles for administrator review.
- New publisher submissions are not shown in public news until an administrator approves them.
- The administrator dashboard has a review queue with article details and the source URL, plus **Approve and publish** or **Request changes** actions. A review note is shown to the publisher so they can update and resubmit the story.
- The publisher's **My articles** list shows status, review notes and actions that are available for each status.
- The public news feed and recommendations show only approved custom articles (plus the illustrative sample articles).

These workflow changes are implemented with browser local storage for demonstration only. The administrator and publishers must use the same browser profile to see shared demo records. This does not provide real multi-user access control or secure government publishing. A live deployment requires server-side authentication, role-based authorisation, a database, audit logs and secure approval endpoints.
